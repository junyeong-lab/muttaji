## 일반 웹앱에서 직접 고치는 사항

- 필수·우대 구간 경계를 잘못 이어받아 근무시간·복지·전형절차·제출서류가 섞이는 오류
- ‘지원 대상’ 같은 표제어를 놓쳐 필수요건이 누락되는 오류
- 원문 한 줄에 `[자격요건]`과 `[우대사항]`이 함께 있는 표를 한 조건으로 합치는 오류
- ‘우대함’·‘가점 부여’와 같은 명시적인 우대 표현을 필수로 표시하는 오류
- 채용공고 템플릿의 `상세내용을 입력하세요`를 실제 우대요건으로 오인하는 오류

## Codex 작업 시 준수 사항

1. 원문과 인용 근거 행을 유지하고 없는 자격·경력을 만들어내지 않습니다.
2. 설명 생성은 `확인 필요 → 미충족 → 부분 충족 → 충족` 상태를 임의 변경하면 안 됩니다.
3. 사용자가 요청하지 않은 외부 AI 호출이나 새로운 정보 전송은 하지 않습니다.
4. 실제 공고 URL 50건에서 문제가 재현되면 문제 공고 ID와 비교 전·후 결과를 함께 남깁니다.
5. 현재 이 파일에 적힌 과제는 **미완료**이며, 사용자가 이후 Codex 작업을 지시하면 그때 구현·회귀 테스트를 진행합니다.

## 로드맵 내용 재검증에서 남긴 추가 Codex 항목

- **복수 모집 유형/신입·경력 조건 해석 (50건 중 의미 검토 21건):** 21건은 자동 경고가 있는 자료이지 21건 모두 오류라는 뜻은 아닙니다. 각 모집 유형과 나의 실제 지원 유형이 다른 조건을 한꺼번에 평가하지 않도록 명시적 선택·조건 분기 기능을 검토합니다. 기존의 지원 유형별 사례 50190160, 52242444, 53349215, 52030033 등을 우선 사용합니다.
- **조건이 여러 개인 한 행의 분리 및 출처 인용 (50186173):** 분리 전·후 모든 조건이 같은 실제 원문 행으로 추적되고, 자격증 한 개만 소유했다고 복합 경력까지 충족 처리되지 않도록 합니다.
- **로드맵 내용 의미 적합성 평가:** 규칙 기반 3단계는 일반 앱에서 개선했습니다. 향후 AI Agent가 추가 설명을 제공하더라도 실제 공고의 필수/우대 구역, 사용자가 선택한 상태, 증빙 출처, 실무·실습 구분을 그대로 유지해야 합니다. 추측한 교육 기간·보유 자격증·합격률·상용 운영 경력은 생성 금지합니다.
