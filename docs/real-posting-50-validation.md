## 고정 목표

사람인·잡코리아 실제 공고 **고유 URL 50건**, 자격증 DB 11개 분야 모두 포함. 각 공고에서 실제 본문 수집 → 필수/우대 분류 → 입력한 자격증과 학력 일치 비교 → 근거 연결 → 로드맵 단계 3개 생성 및 상태 보존을 확인합니다.

- 소스: 잡코리아 38건, 사람인 12건.
- 분야 구성: 정보보안 9건 · 클라우드 3건 · 소프트웨어 9건 · IT 3건 · 네트워크 5건 · 데이터 4건 · 시스템 6건 · 데이터분석 3건 · 개인정보보호 3건 · 정보통신 2건 · 정보보호 3건.
- 검증 대상 URL: `tests/fixtures/real-postings-smoke.json`. 사이트의 개별 채용 상세 URL로 확인된 후보이며, 모든 URL의 현재 접수 가능 여부·본문 수집 가능 여부까지 확인된 것은 아닙니다.
- 실제 브라우저 확인과 코드 모듈 검증을 구별합니다. 자동화 테스트가 정상 종료돼도 원문에서 세부 요건을 빼먹거나 잘못 분류한 경우 수동 검수 전에는 완전 검증으로 표시하지 않습니다.
- `requires-human-review`, `not-completed`, `module-chain-pass`를 개별 기록합니다. 접근 제한, 원문 미제공, 마감·삭제는 확인 가능한 원인을 기록하고 성공으로 둔갑시키지 않습니다.
- 안전한 오류 수정은 일반 앱 코드에서 직접 수행합니다. AI Agent 문제는 나중에 Codex 수정 지시로 분리합니다.

## 신규 24건

신규 후보는 게시된 실제 채용 공고의 고유 상세 링크를 우선 확보했습니다. 과거에 게시된 공고가 포함될 수 있으므로 링크 유효성·공고 본문·마감 상태를 검증해야 합니다. 테스트 결과와 사유는 `Real posting pipeline smoke test` GitHub Actions 실행 기록에 남습니다.

## 재현 및 통과 조건

1. `npm ci && npm test`: 자격증명 정확 일치, 학력 보수적 판정, 원문 인용, 상태 순서, 11분야를 포함한 가상 회귀 검증.
2. `node scripts/validate-real-postings.mjs`: 사전 식별된 실제 공고 상세 URL을 한 번씩 순차 요청; robots·로그인·보안 제한 우회나 자동 재시도 금지.
3. 실제 공고 검증 통과는 수집 본문 존재뿐 아니라 요구사항과 원문의 정확한 대응까지 확인해야 합니다. 분류 과잉·누락 및 소스 데이터 불충분은 추가 검토입니다.
4. 운영 사이트는 사용자 프로필의 전체 내용이나 원본 IP를 원격 테스트 로그로 전송하지 않습니다.
