# 뭐따지? Agent 1차 구현 — 계약·정책·Mock

기준: main `ebd3140110ba88354c1c63bc634d877f26cbc0f4`. 로컬 작업 브랜치: `feat/agent-mock-contracts`.

## 구현 범위

- 기존 공고 분류·수정·OCR·역량 비교·로드맵·프로필 저장 코드를 유지합니다.
- 새 `api/agent-analyze.js`와 `lib/agent/`에 독립적인 계약·정책·근거 검증·Mock 어댑터를 추가합니다.
- 기본 모드는 disabled입니다. 새 모드 선택은 서버의 `MUTTAJI_AGENT_MODE`가 정확히 `mock`인 경우에만 허용합니다. 기존 AI 환경변수는 새 API를 활성화하지 않습니다.
- `live` 및 알 수 없는 모드는 disabled로 처리합니다. 실제 제공자 SDK·키·URL·외부 진단·재시도·모델 fallback은 추가하지 않습니다.
- 이번 변경은 환경변수를 설정하지 않습니다. 데모는 의존성 주입으로 한 함수 인스턴스만 Mock으로 실행합니다.
- 웹 화면과 기존 비교·로드맵에는 아직 연결하지 않습니다. 사용자의 기존 상태와 수동 분류를 변경하는 경로가 없습니다.

## 로컬 확인

의존성 설치 없이 Node.js 24에서 검증했습니다.

```powershell
npm test
node scripts/agent-mock-demo.mjs
```

데모는 가상 공고·가상 프로필을 사용해 Web Request를 메모리에서 처리합니다. HTTP 서버를 열거나 외부 통신을 하지 않으며 환경변수를 변경하지 않습니다. 결과는 합성 예제에 관한 JSON이며 `모의 결과 · 실제 AI 분석 아님` 표시를 포함합니다.

## 요청·응답 계약

POST 본문은 `{consent:true,input}`입니다. 알 수 없는 필드는 거부합니다.

`input` 필드:

| 필드 | 내용 |
| --- | --- |
| schemaVersion | 정수 1 |
| revision | 클라이언트가 관리할 입력·수정 버전, 영숫자·밑줄·하이픈 1~64자 |
| posting | 원문 공고, 20~8,000자·400줄 이내 |
| profile | goalJob, education, experience, certificates, skills 문자열, 각각 2,000자 이내 |

Mock은 `mockExample()`과 정확히 일치하는 합성 공고·프로필만 허용합니다. revision은 바꿀 수 있습니다. 실제 프로필, 일부를 수정한 예제, 공고·프로필의 지시문 추가는 `MOCK_FIXTURE_ONLY`로 거부합니다. 공개 Mock 엔드포인트를 개인정보 분석 API로 사용하면 안 됩니다.

응답은 schemaVersion, revision, mode, label, needsHumanReview, requirements만 포함합니다. 조건마다 다음 정보를 제공합니다.

- 공고 인용으로부터 계산한 요건 ID, required/preferred/unresolved 분류
- 해석, 중요하게 본 이유, 확인 질문, 다음 행동
- 공고 근거와 프로필 근거: source, field, start, end, quote, ID
- 관련성: related / explicit-gap / not-stated

`related`는 경험이 관련 있다는 뜻이며 충족 판정이 아닙니다. `explicit-gap`은 본인이 부족하다고 명시한 예제입니다. `not-stated`는 정보 부재이며 미충족 판정이 아닙니다. 최종 status, 확률, score 필드는 계약에서 허용하지 않습니다.

근거 위치는 JavaScript 문자열의 UTF-16 인덱스이며 end는 제외 범위입니다. 공백·개행·유니코드를 정규화하지 않고 원문 substring과 정확히 대조합니다. 전체 해당 필드의 SHA-256 해시와 위치를 ID에 포함하므로 필드 변경 후 이전 인용을 재사용할 수 없습니다. 인용 존재는 해석의 정확성이나 사용자 이력의 진실성을 보증하지 않습니다.

## 안전 경계

- disabled는 POST 본문을 읽기 전에 거부합니다. Mock에서도 consent가 정확히 true여야 합니다. 현재 consent는 서버에서 합성 예제를 처리하는 동의이며, 향후 외부 AI 전송 동의를 대신하지 않습니다.
- 클라이언트 요청으로 모드·제공자·어댑터를 선택할 수 없습니다. 어댑터 주입은 내부 테스트용입니다.
- JSON 형식·메서드·Origin을 검사하고, Content-Length 유무와 관계없이 스트림에서 UTF-8 바이트 수를 세어 64,000바이트 초과를 중단합니다.
- 어댑터 입력을 복사하고 검증 원본은 따로 보유합니다. 출력의 추가 필드, 잘못된 근거·출처·요건 ID·revision·빈 결과를 거부합니다.
- 어댑터 시간 제한은 2초이며 abort signal을 전달합니다. 함수 실행 제한은 5초로 제안 설정했습니다. 중단을 무시하는 임의 어댑터의 실행 자체를 강제로 종료하는 샌드박스는 아닙니다.
- 요청·응답·예외·키를 로그에 기록하지 않습니다. 저장소·DB·파일·쿠키에 입력이나 결과를 저장하지 않고 응답에 no-store를 적용합니다.
- API 응답은 JSON입니다. 다음 UI 단계에서는 반드시 textContent로 표시하고 revision이 바뀐 결과를 폐기해야 합니다.
- 기존 `/api/analyze`의 코드와 환경변수는 그대로입니다. 그 API의 향후 활성화를 새 API가 통제하지는 않습니다.
- Mock에는 합성 예제만 있으므로 개인 인증 코드를 추가하지 않았습니다. Origin 검사는 인증·분산 요청 제한을 대신하지 않습니다. 향후 공개 운영·live 연결 전에는 별도의 접근·사용량 통제가 필요합니다.

## 테스트와 한계

기존 52개 테스트와 신규 11개 테스트를 실행합니다. 신규 검증은 요청 계약, 반복 인용·CRLF·공백, 근거 위조, 미입력/부족 구분, 동의·비활성화·live 차단, 지시문 삽입 거부, 자동 충족·점수 필드 거부, 오래된 revision, 어댑터 오류·비JSON·시간 초과, 스트림 바이트 제한, 네트워크 차단 상태에서의 Mock API 요청/응답을 포함합니다.

기존 테스트는 루트의 type:module 설정에서 브라우저 UMD 소스를 require하여 실패했습니다. 앱 코드는 그대로 두고 `tests/load-browser-module.cjs`가 기존 CommonJS 분기를 명시적으로 평가하도록 테스트 import만 보완했습니다. 기존 단언은 변경하지 않았습니다.

Mock 테스트는 실제 모델의 인젝션 저항성·분류 정확도를 검증하지 않습니다. 이번 인젝션 검증은 예제 외 입력이 실행 경계를 통과하지 않는지 확인합니다. 계약 검증만으로 근거와 의미상 모순되는 모든 자연어를 탐지할 수는 없습니다. 실제 모델 연결 시 별도 평가와 사람의 검토가 필수입니다.

브라우저 UI, 실제 OCR, Vercel 빌드·운영 배포는 이번 검증 범위가 아닙니다. 이번 작업에서는 Push·커밋·배포·결제·환경변수 변경을 하지 않습니다.
