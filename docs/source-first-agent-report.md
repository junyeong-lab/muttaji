# 원문 중심 AI Agent 개편 보고서

작성: 2026-10-29 · 브랜치: `feat/agent-semantic-analysis`

**새 아키텍처와 승인 연결의 모의·브라우저 테스트는 통과했습니다. 실제 모델 의미 분석은 미실행이므로 전체 작업 완료나 실제 AI 정확도 검증 완료로 보고하지 않습니다. 운영 배포는 하지 않습니다.**

## 1. 이전 구조와 변경 후 구조

이전에는 일반 분류기가 만든 필수·우대 목록을 `/api/model-analysis`에 전달했습니다. AI는 주어진 ID별 보조 설명만 반환하므로 표의 업무 셀이 필수로 오분류돼도 해당 목록에 종속됐습니다. 기존 경로에는 20요건 제한도 있습니다.

새 기본 흐름:

1. URL에서 가져와 확인한 본문 또는 직접 입력한 **원문 전체**를 사용합니다.
2. 별도 전송 동의와 `AI 원문 분석` 클릭 후, **원문·행 번호만** 같은 인증 API의 `classify-posting` 작업에 전달합니다. 규칙 분류 목록, 사용자 프로필, 자격증 DB는 이 요청에 없습니다.
3. AI는 기업, 직무·부서, 업무, 필수, 우대, 참고, 확인 필요의 7개 범주를 제안합니다.
4. 서버가 정확 인용·위치·근거·명시적 의무 충돌·전체 행 범위를 검사합니다. 미완료 응답은 검토 가능한 성공 결과로 반환하지 않습니다.
5. 화면에는 **AI 제안 · 미승인**으로 표시합니다. 사용자가 분류, 인용, 이유, 적용 직무·지원 유형, 비교 포함 여부를 수정하고 원문 항목을 추가할 수 있습니다.
6. 사용자가 전체 원문 검토 체크와 `검토한 조건 확정`을 수행해야만 `ai-user-approved` 입력을 만듭니다.
7. 확정한 필수·우대만 기존 내 역량 비교로 전달합니다. 자격증 정확 일치·학력 비교·4개 상태·본인 판단·3단계 로드맵은 기존 구현을 사용합니다.

기존 개인 경험 연결 AI는 별도 보조 단계로 유지하며, 공고 승인 전에 이를 실행해 일반 분류 목록으로 우회하지 못하도록 연결했습니다. 추가 모델 요청은 자동 실행하지 않습니다.

## 3. 데이터 계약

요청 예시(실제 실행 결과가 아닌 계약 예시):

```json
{
  "task": "classify-posting",
  "request": {
    "schemaVersion": 1,
    "revision": "posting-example",
    "posting": "우대사항\nSQLD 보유자",
    "source": {"type": "manual"},
    "consent": {"externalAi": true}
  }
}
```

URL 수집 결과는 별도로 확인된 `source.type=url`, `url`, `reviewed=true`를 사용합니다. 이 분석 경로는 URL을 다시 방문하지 않습니다.

모델 출력은 `schemaVersion`, `revision`, `mode=posting-classification`, `complete`, `items`, `referenceRanges`로 구성됩니다. 항목의 구조:

```json
{
  "id": "p1",
  "category": "preferred",
  "quote": "SQLD 보유자",
  "line": 2,
  "endLine": 2,
  "reason": "원문의 우대사항 구간에 명시된 조건입니다.",
  "basisQuote": "우대사항",
  "roleQuote": "",
  "applicantType": "unclear",
  "applicantQuote": "",
  "relation": "single",
  "uncertainty": ""
}
```

- `category`: company / role / responsibilities / required / preferred / reference / unresolved.
- `basisQuote`: 필수·우대 판단에 필요한 실제 원문 근거. 표의 `자격요건` 열 제목만으로 뒤 셀 전체를 필수화할 수 없습니다.
- `roleQuote`: 확인 가능한 적용 직무의 원문 근거. 사용자 목표 직무를 대신 넣지 않습니다.
- `applicantType`: common / new / experienced / unclear. 특정 유형에는 실제 원문 근거가 필요합니다.
- `relation`: single / and / or / mixed / unclear. 자격증 예시나 혼합 논리를 단일 필수 자격으로 바꾸지 않도록 지시하고, 불확실성은 별도로 표시합니다.

서버는 인용을 원문과 대조해 UTF-16 시작/끝 위치와 실제 행을 계산하고 `location`, `scopeEvidence`를 추가합니다. 참고 범위는 모델이 지정한 행 범위에서 **서버가 원문을 그대로 복원**해 사용자에게 표시합니다. 숨겨진 제외 데이터로 버리지 않습니다.

모든 비어 있지 않은 행이 항목 또는 참고 범위에 포함돼야 합니다. 미포함 행, 중복 참고 범위, 잘못된 인용·위치, 명시적 우대의 필수화, 부정형의 필수화, 경력 전용 조건의 신입 적용, 불명확한 경력 기간 충돌 등을 검사합니다. 실패 시 고정 오류 코드와 숫자 행 번호만 반환합니다.

정상 검증 응답도 `approvalRequired=true`인 초안입니다. `complete=true`는 **구조적 행 범위 검사**의 통과이며 한국어 의미나 한 행 안의 모든 조건을 독립적으로 증명했다는 뜻이 아닙니다. 전체 원문과 참고 범위를 검토한 사용자의 승인은 별도입니다.

## 7. 보호한 경계 및 남은 문제

- API 경로·인증·세션·CSRF·공유 예산 저장소를 새로 만들지 않고 기존 경로를 재사용합니다. 새 작업도 유료 실행 직전에 같은 model 할당량을 예약합니다.
- 원문 단계에는 사용자 프로필을 전송하지 않습니다. 별도 경험 보조 단계는 기존 전송 동의가 다시 필요합니다.
- 원문·선택 범위는 신뢰할 수 없는 데이터이며 도구·스크립트·명령으로 실행하지 않습니다. UI는 `textContent`와 폼 값으로 표시합니다.
- 원문이 바뀌면 초안·승인·기존 비교/로드맵 연결을 무효화합니다. AI 실패만으로 원문, 프로필, 기존 사용자 판정을 지우지 않습니다.
- 새 분류는 기존 20개 목록에 종속되지 않지만, 입력 20,000자·400행, 모델 항목 60개와 참고 범위 60개, **출력 4096토큰** 등 제한은 유지합니다. 긴 공고는 출력 부족·누락으로 실패할 수 있습니다. 자동 분할 유료 요청·재시도·상한 증가는 없습니다.
- 정확 인용과 구조적 범위 검사는 모든 한국어 의미를 증명하지 못합니다. 한 물리 행의 여러 조건 누락, 참고로 잘못 분류한 조건, 자유 서술 이유의 부적절한 추론 등은 실제 모델 결과와 원문을 대조해 평가해야 합니다. 사용자의 전체 원문 검토·승인을 생략할 수 없습니다.
- `relation`은 혼합 논리와 불확실성을 보존하는 정보이며, 임의의 중첩 논리식을 수학적으로 판정하는 엔진은 아닙니다.
- 기존 비교와 일반 로드맵의 내용 오류는 이번에 수정하지 않습니다. 일반 분류기 고도화 역시 별도 작업입니다.

**남은 우선순위:** 승인된 미리보기 환경에서 대표 두 공고를 실제 모델로 검증 → 원문·분류·범위·참고 제외를 대조 → 남은 50건을 기존 호출·예산 범위 안에서 별도 평가. 이 절차가 끝나기 전에는 실제 모델 정확도 검증 완료로 보고할 수 없습니다.
