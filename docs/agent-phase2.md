## 이번에 추가한 동작

채용공고 화면에서 **가상 예제 결과 보기**를 누르면 보안 로그 분석 경험, Linux 운영 경험, SQLD 보유에 관한 모의 결과를 표시합니다. 공고 인용, 가상 지원자 입력 인용, 조건 해석, 추가 확인 사항, 다음 행동을 함께 제공합니다. 원문 공고와 가상 프로필은 펼쳐 볼 수 있습니다.

화면에는 **모의 결과 · 실제 AI 분석 아님**을 표시합니다. 관련 경험과 기업의 충족 인정은 구분하고, 정보 미입력을 미충족으로 취급하지 않습니다.

현재 공고·프로필의 값을 읽지 않습니다. 예제는 입력창을 덮어쓰지 않으며 기존 비교 상태나 로드맵으로 채택하는 버튼도 없습니다. 합성 데이터를 실제 사용자 경험으로 오인해 반영하는 것을 막기 위한 범위입니다.

## 데이터 흐름

`예제 버튼 → 같은 사이트 data/agent-mock-example.json GET → 입력·출력 계약 및 인용 검사 → textContent로 표시`

새 API를 활성화하거나 외부 모델을 호출하지 않습니다. 로컬 사본의 정적 예제를 읽는 요청만 발생하며, 개인 데이터가 담긴 POST는 없습니다. 배포된 환경에서 실행한다면 해당 사이트에서 정적 예제를 내려받는 GET 요청은 발생합니다.

정적 예제는 `scripts/generate-agent-mock-fixture.mjs`가 1차 구현의 Mock 어댑터와 검증 서비스를 사용해 생성합니다. 테스트가 정적 예제와 서버 Mock 결과의 완전 일치를 확인하므로 두 결과가 조용히 달라지는 것을 방지합니다.

브라우저에서는 계약과 원문 위치·인용 일치를 검사합니다. Node 서버에서 수행한 SHA-256 ID 검증을 브라우저가 다시 수행하지는 않습니다. 테스트에서 생성 결과 일치를 확인하고, 화면의 모든 문구는 HTML 실행 없이 텍스트로 표시합니다. 인용 검사는 해석의 의미상 정확성을 보증하지 않습니다.

위 동작은 결과를 숨기고 진행 중 요청을 중단합니다. 응답이 늦게 오거나 취소를 무시하더라도 revision과 요청 세대가 달라지면 표시하지 않습니다. 실패·시간 초과 시 버튼을 다시 사용할 수 있으며 기존 기능은 계속 동작합니다.

- 기존 52개, 서버 계약·정책 11개, 화면 관련 5개로 총 68개 자동 테스트.

- HTML 형태의 응답 문구가 이미지·스크립트로 실행되지 않고 텍스트로 남는지 확인했습니다.
- 로컬 실제 브라우저에서 예제 세 조건·근거 표시, 공고 수정 시 숨김, 수동 분류 수정 시 숨김을 확인했습니다.

실제 OCR 정확도, 모바일 실기기, Vercel 빌드·배포, 실제 모델 해석 정확도는 이번 검증 범위가 아닙니다. Push·커밋·배포·유료 호출·환경변수 변경은 수행하지 않았습니다.
