## 3. 의미 분석 계약과 처리

기존 `schemaVersion: 1`, 요건 ID, 인용, 제안 상태, 이유, 행동, 자격증 제안 구조를 유지합니다. 실제 SDK 응답에는 다음 `semantics`가 추가됩니다.

```json
{
  "units": [{
    "quote": "원문에서 정확히 복사한 의미 단위",
    "obligation": "required",
    "roleScope": "specific",
    "roleQuote": "원문의 적용 직무 제목",
    "applicantType": "experienced",
    "applicantQuote": "원문의 경력 지원자 적용 문구",
    "relation": "start"
  }],
  "uncertainties": [{
    "quote": "불명확하거나 충돌하는 실제 공고 문구",
    "reason": "확정하지 못한 관계에 대한 보조 의견"
  }]
}
```

위 JSON은 구조 설명용 발췌이며 실제 요청·결과가 아닙니다.

- `obligation`: `required / preferred / not_required / unclear`.
- `roleScope`: `common / specific / unclear`. 공통·직무별 주장을 하는 경우 원문 범위 근거 필수.
- `applicantType`: `common / new / experienced / unclear`. 특정 지원 유형 주장을 하는 경우 원문 근거 필수.
- `relation`: 첫 단위는 `start`, 이후 `and / or / unclear`. 명시적 `및·또는·혹은`은 분리하고 실제 연결어와 대조합니다. 혼합 논리의 우선순위를 임의 확정하지 않습니다.
- 단위 1~8개, 불확실성 0~4개. 원문 순서·내용 누락·다른 조건 인용·부정형 왜곡·명시된 필수/우대 반전을 차단합니다.
- 범위 인용은 공고에 실제로 존재해야 합니다. 뒤쪽 신입 제목을 앞쪽 경력 조건에 붙이거나, `[경력]` 구간에서 앞의 `[공통]`만 인용하는 사례를 차단합니다. 모든 한국어 구간 형태를 규칙으로 증명하는 기능은 아닙니다.

서버는 검증 후 `semantics`를 `semanticAnalysis`로 변환합니다. 인용별 UTF-16 시작/끝 오프셋, 1부터 시작하는 행·열과 끝 행을 **원문에서 직접 계산**합니다. 같은 인용이 반복되면 최대 32개 후보 위치를 남기고 문맥 확인을 안내합니다.

`roadmapSupplement`는 해석·현재 역량 관계·조건별 행동·공고 위치·프로필 인용과 `advisoryOnly: true`를 포함합니다. 기존 3단계 로드맵이나 본인 판정에 쓰는 갱신 경로는 없습니다. AI 설명 영역의 기존 준비 행동으로 제공합니다.

### 필요한 최소 입력 확장

`requirements[].conditionQuote`는 선택한 조건의 정확한 문구입니다. `sourceQuote` 안에 존재해야 하며, 기존 원문 전체도 유지합니다. 한 물리 행에 필수·우대·다른 조건이 함께 있는 경우 다른 조건까지 반복 분석하는 것을 막습니다. 이 필드가 없는 기존 호출은 기존 `sourceQuote`를 사용합니다.

선택 정보가 있는 API 호출만 다음 선택적 필드를 사용할 수 있습니다.

```json
{
  "analysisContext": {
    "selectedRole": "관리진단 컨설팅",
    "applicantType": "experienced"
  }
}
```

이는 `request` 안의 선택적 필드이며, 지원 유형은 `new / experienced / unspecified`입니다. 생략 시 선택 직무 없음·유형 미선택으로 처리합니다. 프로필의 목표 직무를 사용자 선택으로 대체하지 않습니다. 이번 작업에서 이 값을 입력하는 UI는 만들지 않았습니다.

일반 파서가 기타로 보관한 명시적 부정형 문장은 AI 요청에만 추가할 수 있습니다. 50190160의 기존 일반 요건은 19개 그대로이며, AI 전용 검토 문장 1개를 추가해 20개로 분석합니다. 20개 한도나 길이 때문에 추가하지 못한 문장은 `semanticCoverage.pending`에 남깁니다. 일반 분류 결과는 변경하지 않습니다.

## 5. 사용자 역량·로드맵 보완 사례

지시서에서 필요한 경험 유형만 가상 지원자 프로필로 재구성했습니다. 실제 학교명·소속 교육과정 이름·구체적인 군 직책을 제거했으며, 이름·연락처·계정 키·실제 상세 이력 문서를 포함하지 않습니다. 공개 공고 스냅샷의 이메일·전화번호도 같은 길이로 마스킹해 행·오프셋을 유지했습니다. 테스트 시 외부 AI로 전송하지 않았습니다.

- 이미 보유했다고 입력한 정보처리기사·SQLD·네트워크관리사 2급의 재취득 권고를 걸러냅니다. 준비 예정·미취득 입력은 보유로 간주하지 않습니다.

## 9. 미해결·추가 검증 필요

1. **실제 모델 6건 우선 검증 및 나머지 44건 평가가 남아 있습니다.** 이번 모의 검사는 모델의 자연어 추론·권고 관련성을 증명하지 않습니다.

3. 최대 8개 의미 단위와 4096 출력 토큰을 유지했습니다. 긴 공고에서 응답이 잘리거나 계약 검증에 실패할 수 있으며, 실제 모델로 길이·거부율을 측정해야 합니다. 자동 재시도나 토큰 한도 증가는 없습니다.

7. 직무·지원 유형 선택 UI는 범위 밖입니다. 명시적 선택 정보가 없는 직무별/유형별 조건은 구분해 설명하고 판정 보류합니다.
