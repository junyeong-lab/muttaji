# 실제 모델 연결 및 검증 기록 (2026-10-27)

> 최신 상태: 사용자가 로컬 OpenAI 키를 설정하고 가상 공고 및 실제 공고 분석 성공을 확인했습니다. 아래 초기 미승인·미연결 항목은 당시 기록입니다. 최근 코드 정리까지 자동 테스트 160개 통과. 실제 키·이력·응답 원문은 이 문서에 저장하지 않습니다. 운영 배포는 미진행입니다.

## 완료한 코드

AI SDK 7.0.154, OpenAI provider 4.0.103을 정확한 버전으로 고정했습니다. 기존 Mock·규칙 비교 API와 별도로 로컬 `/api/model-analysis`를 연결했습니다. 서버에서 모델 객체를 주입하는 공통 어댑터와 JSON 출력 계약을 사용해 제공자 교체가 가능합니다.

내 역량 화면의 새 AI 분석 영역에서 전송 동의·테스트 접근 코드를 확인한 뒤에만 POST합니다. 공고와 현재 역량 5개 필드 및 공고 필수/우대 요건을 보냅니다. 실제 API 키·사용자의 상태 선택·판단 근거 입력란은 보내지 않습니다. 결과에는 공고·프로필 인용, 경험 연결, 제안 상태, 다음 행동 및 DB 내 자격증 참고 제안을 표시합니다. 결과는 별도 화면에만 표시하고 기존 상태·로드맵은 덮어쓰지 않습니다. 현재 단계에서 AI가 공고 분류 자체를 새로 작성하거나 기존 로드맵에 자동 반영하지는 않습니다.

## 아직 미완료

사용자는 OpenAI API 키 보유만 확인했습니다. 모델·실제 테스트 비용은 아직 승인받지 않았습니다. 키를 읽거나 설정하지 않았고 실제 모델 API 요청은 0회입니다. 실제 분석 품질·계정 모델 접근 권한은 검증되지 않았습니다. 공개 Vercel API는 연결하지 않았으며 운영 활성화 전 별도 인증·공유 요청 제한·영속 비용 제한이 필요합니다.

## 서버 실행 조건

다음 환경변수가 모두 유효해야 로컬 모델 기능이 켜집니다. 이 문서 작성 중 어떤 환경변수도 변경하지 않았습니다.

- OPENAI_API_KEY: 사용자 본인이 로컬 서버 실행 환경에만 설정할 비밀 키
- MUTTAJI_AI_MODEL: 승인받은 정확한 모델 ID
- MUTTAJI_AI_ACCESS_CODE: 16자 이상의 별도 로컬 테스트 접근 코드. 웹 화면에는 이 코드만 입력
- MUTTAJI_AI_ENABLED=true 및 MUTTAJI_AI_OWNER_APPROVED=true: 모델·비용 승인 후에만 설정

실행은 기존 `node scripts/preview-agent.mjs 0 --live-url`입니다. 키는 채팅·브라우저·소스·명령 기록에 직접 붙여넣지 않고 사용자 컴퓨터에서 숨김 입력으로 설정하도록 안내할 예정입니다. 키를 브라우저나 로그에 출력하는 코드는 없습니다. 기존 AI Gateway 환경변수는 사용·변경하지 않습니다.

## 보호 장치와 테스트 범위

기본 비활성화, Origin·접근 코드·개별 전송 동의 검증. 사용자 검토 없는 URL 본문 거부. 요청 32KB, 분석 입력 JSON 24,000자 및 요건 20개 제한. 서버 실행당 최대 3번 모델 요청, 동시 요청 1개, 실패도 횟수에 포함. SDK 자동 재시도 0, 출력 최대 4096토큰, 전체 분석 타임아웃 45초. 앱 로그·분석 저장·SDK telemetry 없음. store:false를 설정하지만 제공자의 오남용 모니터링 등 보관까지 없앤다는 뜻은 아닙니다. 서버 재시작 시 횟수 제한이 초기화되므로 이 제한은 영속적인 달러 예산 차단 장치가 아닙니다.

공고의 명령문은 신뢰하지 않는 데이터로 전달하고 모델에 도구·검색·URL 방문 권한을 제공하지 않습니다. 서버가 실제 공고·프로필에 없는 인용, 허용하지 않은 자격증 ID와 출력 필드를 거부합니다. 이는 의미적 정확성 전체를 보장하는 검증은 아닙니다.

실제 AI SDK의 MockLanguageModelV4로 구조화 출력 경로를 테스트했습니다. 인증·동의 누락 시 호출 0회, 잘못된 인용 거부, 실패 포함 횟수 제한, 동시 요청 차단, UI 동의·클릭 전 외부 분석 없음, 입력 변경 후 늦은 응답 무시, 로컬 HTTP 서버 비활성화 응답을 검증합니다.

## 실제 공고 검증 실패 점검

사용자 화면에서 가상 공고 1건의 실제 모델 정상 응답을 확인했습니다. 이후 실제 공고 응답이 INVALID_AGENT_OUTPUT으로 거부됐습니다. 원문/응답은 저장하지 않으므로 과거 실패 세부 사유는 확인할 수 없습니다.

검증을 단계별 고정 코드로 분리하고 응답 항목 순번만 안내합니다. 공고·프로필·키·모델 원문 응답은 진단에 담지 않습니다. 로컬 상태 조회의 lastValidation에는 실패 종류와 항목 순번만 남습니다. 동적 JSON 스키마가 요청 revision·요건 개수·허용 요건 ID·자격증 ID를 제한하고, 시스템 지침은 요건별 정확한 원문 복사를 명시합니다. 기존의 입력에 없는 인용 거부·근거 없는 상태 제안 거부는 유지합니다. 일부 잘못된 항목을 검증 없이 통과시키지 않습니다.

공고 인용 불일치·경험 인용 불일치·요건 누락/중복·잘못된 자격증·근거 없는 상태 등을 가짜 응답으로 재현했습니다. 전체 149개 테스트 통과. 이번 코드 점검 중 실제 AI 요청은 0회이며 유료 재시도는 하지 않았습니다. 새 스키마의 실제 공고 성공 여부는 다음 실제 테스트 전까지 미검증입니다.


## 비교 대상과 근거 연결 개선

채용 제목과 단독 모집 인원은 각각 직무 후보·기타로 분류하고, 요건별 비교와 AI 입력에서 제외합니다. 기존 분류 수정 결과가 남아 있어도 이 메타데이터는 비교 대상에서 걸러냅니다. 원문 행 번호는 보존합니다.

유관업무 경험에는 관련 업무 수행 근거를, 문서작성에는 보고·분석자료 작성 근거를 연결합니다. 석사·박사는 해당 학위를 직접 언급한 입력만 연결하고 취득을 자동 인정하지 않습니다. 명시적 자격증 조건은 기존 비교기의 자격증 별칭·경계 일치 함수를 재사용해 요구 자격과 일치하는 입력만 연결합니다.

AI 지침에 신입·경력 대안 구분, 인턴·알바 예시로 군·다른 업무 경험을 배제하지 않기, 미입력은 미보유가 아니라는 규칙을 추가했습니다. DB에 이름이 명시된 자격증에 대해 미보유 근거가 없는 미충족 제안은 별도 서버 정책으로 확인 필요로 보정합니다. 사용자 선택 상태는 변경하지 않습니다. 실제 모델의 새 지침 준수 여부는 재호출로 확인하지 않았습니다.

관련 가상 회귀 사례를 추가했고 전체 테스트 153개 통과. 유료 AI 호출·배포 없음. 적용 후 공고 1차 분석과 비교를 다시 실행해야 이전 화면의 요건 목록이 갱신됩니다.


## 분석 표현 기준 정리

분석 지침·검증을 맡는 provider-interface.js에서 결과 표현 정책을 suggestion-policy.js로 분리했습니다. 기존 import 경로는 재수출로 유지합니다. 정책은 검증된 AI 제안의 복사본만 수정하고 사용자 자체 점검 상태나 프로필은 변경하지 않습니다.

명시적으로 열거한 전공 조건에서 다른 전공의 기술·프로젝트 경험을 부분 충족 근거로 삼지 않도록 제한된 규칙을 추가했습니다. 공고 전체에 명시되지 않은 민간 경험·컨설팅 산출물·고객 관련 경험이 missing에 추가된 경우 별도 preparationSuggestions로 옮기고 화면에 '추가 준비 참고 · 공고의 필수요건 아님'으로 표시합니다. 이는 특정 문구에 대한 보완 규칙이며 모든 의미상 과잉 요구를 완전히 판별하는 검사는 아닙니다.

명시적인 신입·경력 대안 문구에서는 신입 지원 가능 여부를 다시 문의하라는 행동을 제거하고, 경력 인정 기준 문의와 실무 정리 행동은 보존합니다. 원문에 실제로 명시된 별도 조건은 보존합니다.

가상 회귀 테스트 전체 160개 통과. 이번 정리에서는 추가 유료 AI 호출·Push·배포를 하지 않았습니다. 최신 정책의 실제 모델 결과는 아직 재확인하지 않았습니다. 공개 운영을 위한 인증·공유 요청 제한·지속적 비용 통제·Vercel API 연결은 별도 과제입니다.
