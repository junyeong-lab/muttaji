# 🐥 뭐따지? (Muttaji)

**AI가 알려주는 나만의 취업 준비 가이드**

> 채용공고를 입력하면 요구사항을 분석하고 사용자 역량과 비교하여, 무엇을 준비할지 실행 순서로 알려주는 웹앱 MVP 프로젝트.

## 현재 상태 (2026-10-26)

- **완료:** 서비스 기획, 기존 캐릭터·디자인 시안, 발표자료, 자격증 DB Excel 원본 및 사용자 선택 34개 JSON 연동, [프로젝트 계획서 v2](./plan.md), 반응형 웹 UI, 메뉴 이동, 채용공고 텍스트 규칙 분류·이미지 OCR, 내 역량 입력 폼 및 **필수·우대 조건별 사용자 자체 점검 UI**, 자체 점검 결과에서 **규칙 기반 준비 순서 생성**. AI 분석 API와 결과 화면은 구현되어 있으며, 보유 자격증명만을 대상으로 한 규칙 기반 자동 일치 표시와 브라우저 프로필 저장을 추가했습니다. 실제 AI 호출은 별도 검증 대상입니다.
- **진행 전:** AI Gateway 고객 인증 및 실제 AI 호출 검증(사용자 결정으로 보류), 이미지 AI 분석, 일반 경력·학력·기술 조건의 자동 확인, 서버 계정 저장, 공식 검증된 자격증 추천, 일정·기간을 포함한 개인별 실행 로드맵.
- **검증 범위:** GitHub 소스 파일 및 JavaScript 문법 확인. 배포된 브라우저 화면에서 `CPPG` 검색 시 과거 23개 중 1개 표시되는 것을 사용자 캡처로 확인했습니다. 분야별 필터는 별도 실제 조작 확인이 필요합니다.
- **자격증 검색(2026-10-22):** 확장본 Excel에서 자격증 23개를 가져와 `data/certifications.json`에 저장하고 검색·분야 필터 UI를 구현했습니다. 제공된 자격 구분·시행기관·응시자격 등은 공식 검증 전 자료이므로 확정 정보로 취급하지 않습니다.
- 「뭐따지?」는 `junyeong-lab/muttaji` 독립 저장소의 루트에서 관리합니다. 기존 `junyeong-lab/Project/muttaji`는 이전 버전의 백업으로 보존합니다.
- 초기 템플릿과 디자인 시안은 **운영 DB나 작동하는 앱이 아닙니다.**

## MVP의 핵심 흐름

채용공고 텍스트/이미지 → 필수·우대 요건 구분 → 내 역량 입력·비교 → 공식 검증된 자격증 정보 매칭 → 취업 준비 로드맵

- 퍼센트 적합도·합격 확률을 임의로 산출하지 않습니다.
- 자격증 보유를 실무 경력 충족으로 간주하지 않습니다.
- 채용공고 URL 크롤링, Google Play 출시, 결제는 초기 MVP 범위가 아닙니다.
- 사용자가 제공한 기존 「뭐따지?」 브랜드 보드의 병아리 포스터를 경량 WEBP로 추출해 [홈 화면](./index.html)에 반영했습니다. 새로운 캐릭터를 생성하지 않았습니다.
- 채용공고 텍스트는 브라우저에서 **규칙 기반 1차 분류**를 제공합니다. `담당업무`, `필수 자격요건`, `우대사항` 등 명시된 제목을 기준으로 구분하며 애매한 항목은 `확인 필요`로 남깁니다. 이 기본 기능에는 서버 전송·저장이 없습니다. **선택적 AI 의미 분석은 2026-10-22 사용자 승인을 받아 서버 설정상 활성화했으며, 실제 모델 응답 검증은 진행 전**입니다. 기본 규칙 기반 분석은 AI 호출 없이 사용 가능합니다.
- 이미지 업로드는 브라우저 미리보기와 **선택적 한글·영문 OCR(Beta)**을 제공합니다. 사용자가 `이미지 글자 추출하기` 버튼을 누르면 Tesseract.js 6.0.0 라이브러리·언어 데이터를 외부 CDN에서 다운로드하여 브라우저에서 인식합니다. 이미지 자체를 앱의 서버로 업로드하지 않으며 추출 텍스트는 사용자가 수정 후 규칙 분류할 수 있습니다. 실제 이미지 OCR의 기기·브라우저별 검증은 아직 필요합니다. 내 역량은 같은 브라우저의 localStorage에만 저장되며, 보유 자격증명과 공고의 명시적 자격증 조건을 규칙으로 대조합니다. 서버 프로필 저장은 없습니다.
- 아직 분석 결과나 실제 추천이 없는 곳에는 개발 예정 상태를 명시했습니다.

## 개발 기록 · 2026-10-22 · 채용공고 이미지 OCR(Beta)

- 규칙 기반 텍스트 분류 결과는 사용자가 직접 제공한 화면에서 기업명·모집 직무·담당업무·필수조건·우대사항 및 원문 줄 번호 정상 표시 확인.
- `assets/image-ocr.js`: 사용자 클릭 시에만 한글·영문 OCR 모듈을 로드하고, 이미지의 텍스트를 추출해 편집 가능한 공고 텍스트 칸에 넣음.
- 실수 방지: 잘못된 파일 형식·8MB 초과 거부, 기존 텍스트를 덮어쓰지 않고 추가, 20,000자 초과 시 유지, 처리 중 이미지가 바뀌면 이전 결과 미적용, 예외 안내.
- 검증: JS 파싱 확인, 가짜 OCR Worker를 사용한 파일 선택 → 버튼 클릭 → 텍스트 채우기 → 규칙 기반 분류 통합 테스트 통과. 실제 한글 이미지와 외부 CDN 로딩은 사용자 브라우저 테스트 필요.
- **개인정보·비용:** 이미지 OCR은 AI Gateway와 무관하며 유료 API 요청을 하지 않음. CDN 코드·언어 데이터 다운로드만 발생. AI 기반 의미 분석은 API 비용·외부 전송 동의 및 안전한 공개 서비스 사용량 통제가 마련되기 전까지 활성화하지 않음.
- 다음 단계: 사용자가 실제 채용공고 캡처에서 OCR 결과 확인 → 안전한 AI 분석 호출 설계 → 역량 비교.

## OCR 개선 · 2026-10-22 · 실제 표 이미지 피드백

- 사용자 제공 엔드포인트 보안솔루션(EDR/AV) 채용공고 표 이미지를 첫 실제 OCR 검증에 활용. 초기 결과에서 한글·영문·숫자 혼합 단어가 잘못 인식되고, 여러 표 열이 뒤섞이는 현상을 확인.
- 실제 이미지: 1152×648 픽셀, 유의미한 텍스트는 상단 약 200px 영역에 집중. 세로 구분선 3개가 있어 독립적인 4개 열로 인식하는 편이 적합함.
- `assets/ocr-image-preprocess.js`: 문자 영역을 기준으로 흰 여백 자동 자르기, 표의 연속된 세로 구분선 감지, 열별 분리, 최대 3배 확대·명암 대비 조정. 표 구분선이 없으면 단일 텍스트 영역으로 처리.
- `assets/image-ocr.js`: 분리한 열을 왼쪽부터 차례대로 OCR 처리, 각 영역의 결과를 결합. Tesseract의 단일 열 페이지 분할 모드(PSM 4) 사용. 동일한 OCR 결과 재실행 시 불필요한 중복 추가 방지.
- 검증: 업로드 원본 이미지의 픽셀 분포에서 세로 구분선 3개 확인, 4열 합성 이미지 분할 테스트, 단일 문서·빈 이미지 예외 및 OCR 모의 실행 확인. **실제 사용자의 브라우저에서 개선 후 OCR 정확도는 아직 검증 전**.
- 개인정보·비용: 이미지의 픽셀 처리와 OCR 인식은 브라우저에서 실행, OCR 라이브러리 및 언어 파일은 사용자 실행 시 CDN에서 다운로드. 유료 AI 의미 분석은 연결하지 않음.

## OCR 표 분류 수정 · 2026-10-22

- 사용자 테스트에서 OCR 추출 글자가 이전보다 읽히지만, 담당업무가 0개로 잘못 나오고 필수/우대 외 내용이 '확인 필요'로 몰리는 사례를 확인. 원본 스크린샷의 별도 열 정보가 OCR 문자열로 합쳐지며 사라진 것이 주요 원인.
- `assets/ocr-column-review.js`를 추가하여 OCR 결과를 **열별로 분리 표시**, 인식 오류를 수정하고 `확인 필요/담당업무/필수조건/우대사항/원문 제목 유지` 분류를 사용자가 선택한 다음 적용하도록 개선.
- 4열일 때 세 번째 열을 담당업무 후보, 네 번째 열을 원문 제목 유지 후보로 **제안**하되, 위치 기준 임시 제안임을 안내하고 사용자 확인 전 확정 분석하지 않음. 회사·부서, 직급을 근거 없이 기업명·모집 직무로 변환하지 않음.
- 검증: `tests/ocr-column-review.test.cjs` 시나리오 5개 통과, 가상 DOM으로 4열 편집 화면 → 텍스트 적용 → 규칙 기반 분류 통합 검사 통과. 4열 예시에서 담당업무 2·필수 1·우대 1·기타 2로 복원.

## AI Gateway 첫 실제 요청 오류 및 무료 진단 · 2026-10-22

- 사용자가 공개 ES기술부 채용공고로 AI 의미 분석을 처음 실행했을 때 UI에 'AI 제공자가 요청을 처리하지 못했습니다'가 표시됨. 이 오류는 서버가 AI Gateway로 요청을 전달했으나 응답이 HTTP 2xx가 아니었던 경우에 반환하도록 작성된 **일반화 오류**이며, HTTP 상태나 오류 원인은 아직 특정되지 않음.
- Vercel 사용자 프로젝트의 Runtime Logs/Runtime Errors 조회가 연결 권한 문제(403)로 실패함. 이 사실을 실제 로그가 없거나 Gateway 요청이 성공했다는 뜻으로 해석하지 않음.
- Vercel 공식 모델 문서상 `openai/gpt-4o-mini` 모델명과 `/v1/chat/completions` API 형식은 지원되는 형식. **400(요청 형식), 401(인증), 402(예산/크레딧), 403(권한), 404(모델), 429(제한)** 등을 구분해야 하며 예산 한도를 임의로 변경하지 않음.
- `api/analyze.js`의 인증된 `POST {diagnose:true}` 요청에서 AI Gateway `GET /v1/models`를 호출하도록 진단 모드를 구현함. **AI 생성/공고 텍스트 전송 없이** API 키 승인 및 모델 목록 포함 여부를 확인. 접근 코드는 기존 `AI_ANALYSIS_ACCESS_TOKEN`이고, 비밀값은 응답에 포함하지 않음.
- 실 AI 호출이 실패하면 원문/모델 오류 메시지를 그대로 보내지 않고 허용된 `gatewayStatus`와 안전한 `gatewayCode`만 표시하여 비밀값·사용자 텍스트 노출 위험을 줄임.
- `assets/ai-analysis-ui.js`에 'AI 연결 진단하기 (모델 호출 없음)' 버튼을 추가, 서버 진단 상태 표시. 별도의 동의 체크나 채용공고 입력 없이 진단 가능하되 접근 코드는 필요함.
- 서버 모의 실행에서 모델 목록 조회, 정상 인증/모델 목록 미포함, 401·402 오류 분류, 권한 검사, 비밀 메시지 비노출 등을 확인함. 실제 Gateway 진단 결과는 사용자 브라우저에서 확인 대기.
- 사용자 첫 실패의 과금 여부는 AI Gateway 대시보드의 Usage/Spend에서 확인 필요. **기존 API 키의 $1 Spend Budget, Never refresh, 7일 만료 설정은 변경하지 않음.**

## AI 연결 진단 2단계 분리 · 2026-10-22

- 사용자 실사용에서 1차 연결 진단이 `진단 실패: 연결이나 서버 응답을 확인하지 못했습니다`로 표시됨. 이 UI 메시지는 브라우저 `fetch()` 거절뿐 아니라 서버의 HTML/비JSON 오류 응답을 `response.json()`으로 처리하다 실패해도 발생했으므로 정확한 원인을 **아직 판명하지 못함**.
- Vercel Runtime Logs/Runtime Errors 조회는 기존처럼 접근 권한 부족(403). 정적 GitHub 파일·운영 배포 상태로는 실제 HTTP 요청의 상태와 응답 본문을 알 수 없음. 공고 텍스트 및 비밀값을 추측하거나 로그로 노출하지 않음.
- 새 `POST /api/analyze` `{diagnose:"local"}`: 서버 토큰 검증과 JSON 처리만 검사하고 **AI Gateway 또는 유료 생성에 전혀 요청하지 않는 로컬 단계**. 기존 `{diagnose:true}`는 이 로컬 단계가 성공한 후에만 외부 Gateway의 무료 모델 목록을 확인.
- `assets/ai-analysis-ui.js`: 1/2단계 앱 서버 및 2/2단계 Gateway를 구분. 서버가 HTML 등의 비JSON 본문을 반환하면 본문/비밀값은 읽어 표시하지 않고 **HTTP 상태와 Content-Type 분류**만 표시. 타임아웃/네트워크 오류/인증 코드도 구분.

- 상태 그룹 제목 및 각 항목 라벨에 같은 SVG 아이콘을 표시합니다. 화면 낭독은 한글 상태명이 담당하며 장식 SVG는 `aria-hidden` 처리합니다. 외부 아이콘 라이브러리나 네트워크 호출은 필요하지 않습니다.
- 상태 순서는 **확인 필요 → 미충족 → 부분 충족 → 충족**이며 충족 판정이 공식 검증을 의미하지 않는 점은 기존과 동일합니다.

## 로드맵 준비 단계 안내 · 2026-10-25

- 기존 상태 순서, 네 가지 색상 아이콘, 조건별 충족 표시 및 본인 입력 근거는 그대로 유지합니다.
- `확인 필요 / 미충족 / 부분 충족` 조건에는 ‘준비 단계 3개 보기’ 접이식 목록을 표시합니다. 경력·학력·자격증·기술 관련 원문 조건에 따라 근거 확인, 학습·실습 및 재확인 순서를 **규칙 기반 예시**로 안내합니다.
- 완료(충족) 조건에는 준비 목록을 추가하지 않으며, 체크리스트를 펼치는 행위로 조건의 상태를 바꾸지 않습니다.
- 공식 검증 전 자격증 DB를 추천 근거로 쓰지 않고, 실습을 실무 경력으로 대신 인정하지 않습니다. 임의 일정/합격 확률, 개인정보 전송 또는 유료 AI 호출이 없습니다.
- `tests/roadmap.test.cjs`에 상태별 안내 및 접이식 화면 렌더링 회귀 검사를 추가했습니다.

## 로드맵 기술별 실습 안내 구체화 · 2026-10-25

- ‘준비 단계 3개 보기’를 조건의 실제 키워드에 따라 구체화했습니다. AWS(IAM·CloudTrail·보안 그룹), Wazuh(에이전트·로그 수집·경보), SIEM, EDR, 보안 점검, 개인정보, 네트워크, Linux, SQL, Python, 클라우드 등에서 안전한 예제 실습과 증빙 자료 정리 방법을 제시합니다.
- '확인 필요' 상태에도 해당 기술의 실습 예시를 보여 주며, 실제 보유 여부 확인 후에만 상태를 사용자가 변경하게 합니다. '부분 충족', '미충족', '충족'의 기존 사용자 판정 기준은 유지합니다.
- 유료 리소스 또는 타인의 환경 사용을 요구하지 않으며 실습과 기업 실무 경력은 분리합니다. AI 모델 호출·개인정보 외부 전송·자격증 공식 검증 없는 추천을 추가하지 않았습니다.
- 제시하는 내용은 규칙 기반 예시이며 공고마다 업무 범위가 다르므로 실제 충족 판정은 사용자 확인이 필요합니다.
- `tests/roadmap.test.cjs`에 기술별·상태별·경력/학력 오인 방지 회귀 검사를 추가했습니다.

- 테스트 항목: Wazuh의 세 상태, Python 로그 분석 자동화 우선순위, 준비 단계 3개 및 사용자 직접 확인 원칙.
