# 🐥 뭐따지? (Muttaji)

**AI가 알려주는 나만의 취업 준비 가이드**

> 채용공고를 입력하면 요구사항을 분석하고 사용자 역량과 비교하여, 무엇을 준비할지 실행 순서로 알려주는 웹앱 MVP 프로젝트.

## MVP의 핵심 흐름

채용공고 텍스트/이미지 → 필수·우대 요건 구분 → 내 역량 입력·비교 → 공식 검증된 자격증 정보 매칭 → 취업 준비 로드맵

- 퍼센트 적합도·합격 확률을 임의로 산출하지 않습니다.
- 자격증 보유를 실무 경력 충족으로 간주하지 않습니다.
- 채용공고 URL 크롤링, Google Play 출시, 결제는 초기 MVP 범위가 아닙니다.
- 사용자가 제공한 기존 「뭐따지?」 브랜드 보드의 병아리 포스터를 경량 WEBP로 추출해 [홈 화면](./index.html)에 반영했습니다. 새로운 캐릭터를 생성하지 않았습니다.
- 채용공고 텍스트는 브라우저에서 **규칙 기반 1차 분류**를 제공합니다. `담당업무`, `필수 자격요건`, `우대사항` 등 명시된 제목을 기준으로 구분하며 애매한 항목은 `확인 필요`로 남깁니다. 이 기본 기능에는 서버 전송·저장이 없습니다. **선택적 AI 의미 분석은 2026-10-22 사용자 승인을 받아 서버 설정상 활성화했으며, 실제 모델 응답 검증은 진행 전**입니다. 기본 규칙 기반 분석은 AI 호출 없이 사용 가능합니다.
- 이미지 업로드는 브라우저 미리보기와 **선택적 한글·영문 OCR(Beta)**을 제공합니다. 사용자가 `이미지 글자 추출하기` 버튼을 누르면 Tesseract.js 6.0.0 라이브러리·언어 데이터를 외부 CDN에서 다운로드하여 브라우저에서 인식합니다. 이미지 자체를 앱의 서버로 업로드하지 않으며 추출 텍스트는 사용자가 수정 후 규칙 분류할 수 있습니다. 실제 이미지 OCR의 기기·브라우저별 검증은 아직 필요합니다. 내 역량 입력은 현재 서버 저장이나 비교를 수행하지 않습니다.
- 아직 분석 결과나 실제 추천이 없는 곳에는 개발 예정 상태를 명시했습니다.

## 개발 기록 · 2026-10-22 · 채용공고 이미지 OCR(Beta)

- 규칙 기반 텍스트 분류 결과는 사용자가 직접 제공한 화면에서 기업명·모집 직무·담당업무·필수조건·우대사항 및 원문 줄 번호 정상 표시 확인.
- `assets/image-ocr.js`: 사용자 클릭 시에만 한글·영문 OCR 모듈을 로드하고, 이미지의 텍스트를 추출해 편집 가능한 공고 텍스트 칸에 넣음.
- 실수 방지: 잘못된 파일 형식·8MB 초과 거부, 기존 텍스트를 덮어쓰지 않고 추가, 20,000자 초과 시 유지, 처리 중 이미지가 바뀌면 이전 결과 미적용, 예외 안내.
- 검증: JS 파싱 확인, 가짜 OCR Worker를 사용한 파일 선택 → 버튼 클릭 → 텍스트 채우기 → 규칙 기반 분류 통합 테스트 통과. 실제 한글 이미지와 외부 CDN 로딩은 사용자 브라우저 테스트 필요.
- **개인정보·비용:** 이미지 OCR은 AI Gateway와 무관하며 유료 API 요청을 하지 않음. CDN 코드·언어 데이터 다운로드만 발생. AI 기반 의미 분석은 API 비용·외부 전송 동의 및 안전한 공개 서비스 사용량 통제가 마련되기 전까지 활성화하지 않음.
- 다음 단계: 사용자가 실제 채용공고 캡처에서 OCR 결과 확인 → 안전한 AI 분석 호출 설계 → 역량 비교.

## OCR 개선 · 2026-10-22 · 실제 표 이미지 피드백

- 사용자 제공 엔드포인트 보안솔루션(EDR/AV) 채용공고 표 이미지를 첫 실제 OCR 검증에 활용. 초기 결과에서 한글·영문·숫자 혼합 단어가 잘못 인식되고, 여러 표 열이 뒤섞이는 현상을 확인.
- 실제 이미지: 1152×648 픽셀, 유의미한 텍스트는 상단 약 200px 영역에 집중. 세로 구분선 3개가 있어 독립적인 4개 열로 인식하는 편이 적합함.
- `assets/ocr-image-preprocess.js`: 문자 영역을 기준으로 흰 여백 자동 자르기, 표의 연속된 세로 구분선 감지, 열별 분리, 최대 3배 확대·명암 대비 조정. 표 구분선이 없으면 단일 텍스트 영역으로 처리.
- `assets/image-ocr.js`: 분리한 열을 왼쪽부터 차례대로 OCR 처리, 각 영역의 결과를 결합. Tesseract의 단일 열 페이지 분할 모드(PSM 4) 사용. 동일한 OCR 결과 재실행 시 불필요한 중복 추가 방지.
- 검증: 업로드 원본 이미지의 픽셀 분포에서 세로 구분선 3개 확인, 4열 합성 이미지 분할 테스트, 단일 문서·빈 이미지 예외 및 OCR 모의 실행 확인. **실제 사용자의 브라우저에서 개선 후 OCR 정확도는 아직 검증 전**.
- 개인정보·비용: 이미지의 픽셀 처리와 OCR 인식은 브라우저에서 실행, OCR 라이브러리 및 언어 파일은 사용자 실행 시 CDN에서 다운로드. 유료 AI 의미 분석은 연결하지 않음.

## OCR 표 분류 수정 · 2026-10-22

- 사용자 테스트에서 OCR 추출 글자가 이전보다 읽히지만, 담당업무가 0개로 잘못 나오고 필수/우대 외 내용이 '확인 필요'로 몰리는 사례를 확인. 원본 스크린샷의 별도 열 정보가 OCR 문자열로 합쳐지며 사라진 것이 주요 원인.
- `assets/ocr-column-review.js`를 추가하여 OCR 결과를 **열별로 분리 표시**, 인식 오류를 수정하고 `확인 필요/담당업무/필수조건/우대사항/원문 제목 유지` 분류를 사용자가 선택한 다음 적용하도록 개선.
- 4열일 때 세 번째 열을 담당업무 후보, 네 번째 열을 원문 제목 유지 후보로 **제안**하되, 위치 기준 임시 제안임을 안내하고 사용자 확인 전 확정 분석하지 않음. 회사·부서, 직급을 근거 없이 기업명·모집 직무로 변환하지 않음.
- 검증: `tests/ocr-column-review.test.cjs` 시나리오 5개 통과, 가상 DOM으로 4열 편집 화면 → 텍스트 적용 → 규칙 기반 분류 통합 검사 통과. 4열 예시에서 담당업무 2·필수 1·우대 1·기타 2로 복원.
- **미해결:** OCR 한글/영문 인식이 틀린 경우 여전히 원문 대조 및 수동 수정 필요. 실제 사용자 브라우저 재검증 대기. AI 의미 분석은 아직 미구현.

## OCR 줄바꿈·가짜 제목 수정 · 2026-10-22

- 사용자 확인: OCR 열별 검토/적용 후 입력창에 **`기타`라는 제목이 자동 삽입**되고, 원래 한 문장인 "EDR/AV 구축 및 유지보수"가 줄바꿈 때문에 두 개의 담당업무로 분류되는 문제 발견.
- 원인: `assets/ocr-column-review.js`의 `compose()`가 제목 보존 선택에도 `기타`를 덧붙이는 오류. `assets/job-text-analyzer.js`가 물리적 줄 단위로 모든 텍스트를 개별 항목 취급하는 구조.
- 수정: 첫 번째 미분류 열과 **원문 제목 유지** 열에서 불필요한 `기타` 생성을 제거. 단, 이미 다른 분류 뒤에 등장한 제목 없는 기타 열에는 분류가 섞이지 않도록 내부의 섹션 구분용 `기타`를 유지.
- 수정: 한글 불릿 `ㆍ` 인식 추가, 바로 다음에 오는 불릿 없는 줄을 앞 항목의 줄바꿈 연장으로 간주해 결합. 새로운 불릿/제목/빈 줄에서는 결합 중단.
- 수정: 통합한 문장의 원문 시작~끝 행 번호를 표시(예: 4~5행).
- 검증: 사용자 제공 공고 문장으로 담당업무 2개, 필수조건 2개, 우대사항 2개, 기타 1개(ES기술부), 회사명 0개 분류 확인. 기존 기능과 신규 회귀 테스트 총 15개 통과, 인라인 JS 구문 확인.
- 제한: 단순 텍스트 규칙 기반 방식이며 OCR의 오인식이나 제목 자체가 사라진 경우에는 수동 확인이 필요함. 실제 배포 브라우저 화면 재검증은 사용자 확인 대기.

## 모집 부서 후보 인식 · 2026-10-22

- 사용자 실사용 테스트: 채용공고에서 `ES기술부`가 '확인 필요'로 표시되고 모집 직무가 0개인 점 개선 요청.
- 원본 표의 `ES기술부`는 구체적 직무명이 아닌 조직/부서명에 가깝기에 직무명이라고 단정하지 않고 **'모집 직무·부서'** 항목에서 '부서명 후보 · 직무명인지 확인 필요' 표시를 함께 제공.
- 규칙: 공고 첫머리, 분류 제목이 아직 없는 상태에서 짧은 조직 이름이 `부·팀·실·센터·본부` 등의 부서 접미사를 가질 때만 후보로 분류. 확정된 회사명/직급/자격증까지 오분류하지 않도록 보수적으로 제한. `모집 부서` 명시적 제목도 인식.
- OCR 열별 검토 화면에서 직접 **모집 직무·부서**를 선택할 수 있도록 옵션 추가.
- 검증: 기존·신규 규칙/열별 입력 테스트 **19개 통과**. 웹페이지 JavaScript 구문 검사는 통과했으며 실제 사용자 브라우저에서 최종 표시 여부 확인 대기.
- 제한: 팀/부서명의 접미사만 보는 규칙은 완전한 의미 분석이 아니므로 원문 확인과 사용자 수정이 필요. AI 의미 분석 및 개인별 비교는 아직 미구현.

## AI 의미 분석 준비 · 2026-10-22

- **서버:** `api/analyze.js`를 Vercel Node.js Function으로 추가. 모델이 실제로 가동될 때에는 Vercel AI Gateway 호환 Chat Completions API의 구조화 JSON 출력을 사용하도록 설계했습니다.
- **결과 항목:** 기업명, 모집 부서, 모집 직무, 담당업무, 필수조건, 우대사항, 확인 필요. AI가 반환한 항목은 입력 원문의 `evidence` 문자열과 일치하는 것만 표시하며, 근거가 존재해도 분류 정확성은 보장하지 않습니다.
- **프런트엔드:** `assets/ai-analysis-ui.js`가 새 'AI 의미 분석' 화면을 담당합니다. 기존 규칙 기반 결과는 그대로 유지하며 AI 결과를 별도 표시합니다.
- **비용·개인정보:** 기본값 `AI_ANALYSIS_ENABLED` 미설정 = 비활성화, 외부 AI 호출 없음. 사용자가 별도의 외부 전송 동의 체크와 비공개 접근 코드 입력 후 직접 실행해야만 공고 텍스트(20~8,000자)가 서버에서 외부 AI Gateway로 전송됩니다. 이미지·프로필은 보내지 않습니다.
- **접근 보호:** `AI_ANALYSIS_ACCESS_TOKEN`을 Vercel 서버 환경 변수로 설정해야 하며 비밀번호/토큰은 저장소나 정적 JS에 포함하지 않습니다. 서버에서 Origin·토큰·동의·길이를 검사합니다. 공개 서비스 사용 전 **Vercel AI Gateway 사용량 제한/예산 설정**이 별도로 필요합니다. 서버리스 환경의 단순 토큰 검증은 분산 호출량 제한을 대신하지 않습니다.
- **활성화 조건:** 사용자의 비용·외부 전송 승인과 예산 설정 이후에만 Vercel 서버 환경 변수 `AI_ANALYSIS_ENABLED=true`, `AI_ANALYSIS_MODEL=<검증된 provider/model ID>`, `AI_ANALYSIS_ACCESS_TOKEN=<충분히 긴 개인 접근 코드>`, `AI_GATEWAY_API_KEY=<뭐따지 전용 예산 설정된 키>`를 사용합니다. **OIDC 인증은 별도의 API 키 예산을 우회할 수 있으므로 사용하지 않습니다.** 실제 사용 전 제공자 데이터 처리 규칙과 모델의 JSON 스키마 지원을 확인해야 합니다.
- **테스트:** 자동화된 서버 모의 검사에서 비활성화 시 유료 API 0회, 잘못된 접근 코드·외부 Origin·동의 없음·긴 입력 차단, 가짜 근거 제거 등 **7건 확인**. 동등한 검사용 `tests/ai-analysis-api.test.cjs` 추가.
- **검증 범위:** GitHub 코드 및 모의 요청 처리와 Vercel 배포 상태만 확인. **유료 AI 모델 실제 호출 및 실제 AI 분석 정확도는 검증하지 않았습니다.**
- **진행 기준:** 중간 점검 1차 제출 완료, 2차는 실제 AI 분석/역량 비교 기능 검증 후 작성할 예정.

## AI Gateway 비용 보호 계획 · 2026-10-22

- Vercel 공식 가이드 확인: 무료 티어는 팀당 월 $5 무료 크레딧을 제공할 수 있으나 **계정의 실제 잔액 및 결제 상태는 별도 확인**이 필요합니다. 크레딧을 구매하면 유료 티어로 전환되고 무료 월 크레딧이 중단될 수 있습니다.
- 안전한 초기 테스트 제안: **전용 AI Gateway API key** 생성 시 총 **$1**, refresh **none**, 만료 **7d**, auto top-up **off**, BYOK **미사용**. 이는 별도 과금 없이 사용 가능함을 보장하지 않고, soft cap이므로 마지막 요청에 한해 한도를 넘길 수 있습니다.
- Vercel Budgets 문서(2026-09-07): API key 지출 제한의 최솟값 $1, API key별 예산 검사는 새 키 생성 후 적용까지 1~2분 걸릴 수 있음. budget은 soft cap으로 제한 초과 요청 한 건이 완결될 수 있음.
- 서버는 전용 `AI_GATEWAY_API_KEY`가 없으면 AI 기능 준비 상태를 `enabled:false`로 반환하며 유료 모델을 호출하지 않습니다. Vercel의 자동 `VERCEL_OIDC_TOKEN`은 비용 제한을 우회하지 않도록 fallback에서 제외했습니다.
- **아직 하지 않은 일:** 사용자 계정에서 키 생성, 크레딧 구매, auto top-up 조작, 예산 설정 확인, 실제 유료 분석 호출, AI 분석 결과 품질 검증.

## AI Gateway 실사용 활성화 · 2026-10-22

- 사용자가 채팅에서 **AI 분석 활성화 및 실제 테스트를 명시적으로 승인**. 이 승인 범위 안에서만 운영 Production에 `AI_ANALYSIS_ENABLED=true` 추가.
- Vercel 환경변수 `AI_GATEWAY_API_KEY`(Sensitive), `AI_ANALYSIS_ACCESS_TOKEN`(Sensitive), `AI_ANALYSIS_MODEL=openai/gpt-4o-mini`, `AI_ANALYSIS_ENABLED=true` 존재 확인. 실제 비밀값은 출력하거나 저장소에 보관하지 않음.
- AI Gateway 키는 사용자 화면에 따라 Spend Budget **$1**, refresh **Never**, expiration **7 days**로 생성. 이 설정을 변경하지 않았음. Gateway budget은 **soft cap**이며 예산 상태/잔액에 따라 제한이 다를 수 있으므로 실제 계정 화면에서 지속 확인 필요.
- `api/analyze.js`는 유효한 전용 API 키와 서버의 별도 접근 토큰이 모두 있어야 활성화되며, OIDC로 우회하지 않음. 방문자는 동의 체크 및 접근 코드를 입력해야만 AI 호출 가능.
- Vercel 공식 안내에 따라 정적 프로젝트의 `.js` 서버 함수가 ES 모듈로 실행되도록 루트 `package.json`에 `type:module` 추가, 기존 기능 테스트는 `.cjs`로 유지.
- **검증 완료:** 활성화 환경변수 존재, GitHub main→Vercel READY 운영 자동배포, 단위/모의 서버 호출에서 입력·동의·접근 통제·원문 근거 필터 확인.
- **검증 전:** 실제 사용자의 Production 브라우저에서 AI 요청이 Gateway로 전달되어 의미 분석 JSON 결과를 반환하는지, 한국어 채용공고 분류의 정확도와 Gateway 사용량 실제값 확인.
- **다음 단계:** 사용자가 접근 코드를 채팅에 노출하지 않고 웹 UI에서 테스트 공고를 제출 후 응답 화면을 확인. 필요 시 Vercel 서버 로그와 사용자 화면으로 오류를 수정.
